# B2 Repair Implementation Plan

> Red before green, one cycle per task, the red observed before any production
> edit. No push, merge, version, publish, or live cursor/registry/config/socket.

**Spec:** `docs/superpowers/specs/2026-09-01-b2-repair-design.md`
**Base:** `d89d983`
**Files:** `lib/peers.py`, `lib/antiphon.py`, `lib/channel.mjs`,
`test/test_peers.py`, `test/test_antiphon.py`, `test/channel.test.mjs`,
`test/test_contracts.py`, `README.md`, `BACKLOG.md`.

### Task 1 — the proof record

**Red:** shape tests for a valid record; and for wrong version, wrong kind,
missing session id, non-canonical session id, malformed digest, torn record and
empty file — every one reading as *no proof*. A test that no proof is not
agreement: an automatic peer without a valid current proof is neither routable
nor deliverable.

**Green:** the record, its digest-named path, strict total validation, and
atomic replace under the existing registry lock. Never rendered.

### Task 2 — the hook writes it, and withdraws only its own half

**Red:** an unnamed Claude hook commits owner→(current UUID, digest) before any
join decision. A hook with an explicit name, and one with a configured-invalid
name, write nothing. The hook removes only an automatic session record whose
owner matches and whose digest is stale; endpoints, explicit peers and other
owners' records are untouched. A retire control that errors or times out is
swallowed and the hook still succeeds.

**Green:** the hook path and the bounded, content-free, single-shot control.

### Task 3 — delivery linearizes at the listener

**Red, the named race:** sender resolves A; hook B commits the proof; the
wakeup is withheld; the sender connects to A's socket. Assert the listener
refuses and that **zero** channel notifications are emitted. A second red:
after the control is released, A's endpoint and socket are gone, B is absent
until a fresh B endpoint exists, and then only B appears.

**Green:** Node validates the proof on every inbound delivery before emitting,
and the listener alone unregisters its pid-owned endpoint and closes only its
channel socket.

**Integration, not units:** this red crosses the real hook, the real Python
resolver and a real Node channel.

### Task 4 — parity

**Red:** a parity suite driving the Python and Node readers over identical
fixtures — valid, different session, missing, wrong version, wrong kind,
malformed digest, non-canonical id, torn, empty — requiring identical verdicts.
Any divergence fails.

**Green:** mirrored Node validation. The plan claims one *format* with two
readers whose agreement is enforced by test, never one implementation.

### Task 5 — configured names

**Red:** the real Codex hook with a positively held writer lock. Absent, empty
and whitespace may observe. `UPPER` normalizes to a valid name and joins.
Present-and-invalid creates no observation, no projection, no route and no
status peer, and Node never probes.

**Green:** a raw-presence predicate kept separate from normalized alias parsing.

### Task 6 — the bounded probe

**Red:** a real child that keeps writing on stdout past the ceiling; another
that keeps writing on stderr; another that sleeps past the deadline. Each
asserts prompt return, that the child and its descendants are dead and reaped,
that retained bytes are within the ceilings, that none of the captured bytes
appear anywhere, and that identity is None. A child writing valid JSON under
the cap still resolves.

**Green:** streaming reads with a deadline, exact stdout and stderr ceilings,
strict decode, `start_new_session` before any group-directed signal, and
terminate→kill→reap. If isolation cannot be established, only the child pid is
signalled.

### Task 7 — privacy

**Red:** route-bearing failures surfaced through reply, Stop, startup, status,
doctor and queue, each carrying an unanchored UUID in mixed case, a full
digest, or an automatic route. Assert the public alias and remedy survive and
every private value is absent. A contract test over `README.md`, `BACKLOG.md`,
`CLAUDE_RULE`, `AGENTS_RULE` and the channel instructions.

**Green:** one central redactor per language applied before truncation,
preserving `refusal_class`; the truncated thread-id prefix replaced by an
aggregate in doctor queue output.

### Task 8 — the reconnect cost, said out loud

**Red:** after A→B, the hook, `status` and `doctor` name the public alias and
an actionable reconnect remedy, and contain no UUID, digest or route. A
mixed-version fixture: an automatic record with no proof fails closed and is
not rewritten or guessed.

**Green:** the wording, and the same sentence in all five written surfaces.

### Task 9 — the exact-SHA gate

Focused suites; `git diff --check`; `py_compile`; `node --check`; full
`npm test`; a clean commit; `fresh-user.sh` on that exact SHA; then the SHA to
the independent reviewer. Any finding starts a new SHA and repeats both gates.

### Task 10 — the reconnect window keeps its evidence

**Red:** hook B commits the proof and listener A self-retires, so the owner has
zero automatic peers. Assert the proof for B still exists, and that `status`
and `doctor` name B's public alias with the reconnect remedy and no UUID,
digest, route or owner key. Then B joins with a fresh endpoint and becomes
routable. Separately: a proof whose owner is positively proved dead is
reclaimed on a mutation path, while a read-only `status` or `doctor` run over
the same state reclaims nothing and leaves a live successor's proof untouched.

**Green:** retention keyed to positively proved owner death on a mutation path
only, with the stored owner key making that proof possible.
