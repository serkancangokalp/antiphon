# B2 Repair Implementation Plan

> Executable. One task per red→green cycle. The red is **run and its failure
> observed** before any production edit in that task. No push, merge, version,
> publish, or live cursor/registry/config/socket state at any point.

**Spec:** `docs/superpowers/specs/2026-09-01-b2-repair-design.md`
**Base:** `d89d983` · **Worktree:** `.worktrees/p0-claude-identity` (one writer)

## Commands used throughout

- focused Python: `/usr/bin/python3 -m unittest discover -s test -k <pattern>`
- focused Node: `node --test test/channel.test.mjs`
- full: `npm test`
- statics: `git diff --check` · `/usr/bin/python3 -m py_compile lib/*.py` ·
  `node --check lib/channel.mjs` · `bash -n test/e2e/fresh-user.sh`
- gate: `test/e2e/fresh-user.sh` on the exact clean commit

## Interfaces introduced

`lib/peers.py`
- `identity_proof_path(cwd, owner_key) -> str` — digest-named, never rendered.
- `write_identity_proof(cwd, owner_key, session_id, digest) -> bool` — build
  whole, atomic replace, under the existing registry lock.
- `read_identity_proof(cwd, owner_key) -> dict | None` — strict total
  validation; every malformed shape returns `None`.
- `reclaim_identity_proof(cwd, owner_key) -> bool` — only on a mutation path,
  only when owner death is positively proved.

`lib/antiphon.py`
- `automatic_ready(cwd, kind, peer, proof) -> bool` — the single three-way
  predicate (endpoint, session half, owner-current proof).

`lib/channel.mjs`
- `readIdentityProof(cwd, ownerKey)` and `automaticReady(...)` — mirrored, with
  parity enforced by test, not by assertion.
