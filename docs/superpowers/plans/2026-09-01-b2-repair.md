# B2 Repair Implementation Plan

> Executable. One red→green cycle per task. The red is **run and its failure
> observed** before any production edit in that task. Every production behaviour
> lands in the task whose red covers it. No push, merge, version, publish, or
> live cursor/registry/config/socket state.

**Spec:** `docs/superpowers/specs/2026-09-01-b2-repair-design.md`
**Base:** `d89d983` · **Worktree:** `.worktrees/p0-claude-identity` (one writer)

## Commands

Every `-k` below is a single unittest pattern — `unittest` has no boolean
argv, so each task's tests share one distinctive token.

| purpose | command |
| --- | --- |
| focused Python | `/usr/bin/python3 -m unittest discover -s test -k <token>` |
| focused Node | `node --test test/channel.test.mjs` |
| full | `npm test` |
| statics | `git diff --check` ; `/usr/bin/python3 -m py_compile lib/*.py` ; `node --check lib/channel.mjs` ; `bash -n test/e2e/fresh-user.sh` |
| gate | `test/e2e/fresh-user.sh` on the exact clean commit |

**Every focused run must report at least one test.** A `-k` pattern that
matches nothing exits zero with `Ran 0 tests` — a green that proves nothing.
Read the count, do not read the exit code.
